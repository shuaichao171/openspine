# Spine Pro 对照审查：第六轮

日期：2026-09-08。延续[第五轮](spine-pro-review-2026-09-08-round5.md)，修复分层 PSD 导入完成后缺少持久来源模型的问题。

## 本轮修改

| 功能 | 原问题 | 修改后的行为 |
| --- | --- | --- |
| PSD 来源 | 导入完成后只保留生成的槽、附件和图集，保存再打开后不知道来源 PSD、隐藏图层设置及图层对应关系 | 文档保存 PSD 路径、画布、忽略隐藏图层设置，以及原始图层索引到区域、皮肤、槽和占位的稳定映射 |
| 导入历史 | 图集和附件可撤销，但没有 PSD 元数据可共同恢复 | 导入、撤销和重做在同一历史项内切换图集、附件结构与 PSD 来源；再次导入后撤销会恢复上一来源 |
| 工程持久化 | 侧车和自动保存无法恢复 PSD 来源 | 编辑器状态格式升级到 v12；普通侧车和自动保存恢复完整 PSD 元数据；只读根侧车继续排除作者状态 |
| 便携工程 | 原生工程未携带原始 PSD，移动工程后来源路径失效 | 完整 ZIP 和原生工程把 PSD 保存到对应骨架的 `psd/` 目录，并分别改写根状态和单骨架侧车中的相对路径 |
| 路径边界 | 包内编辑器状态可能声明绝对路径或越界相对路径 | 包内恢复只接受提取目录中的真实普通文件，拒绝绝对、越界、缺失和符号链接 PSD 路径 |
| 重命名 | 导入后重命名目标皮肤或槽会使未来同步映射过期 | PSD 映射随皮肤和槽重命名迁移；加载其他骨架时清除旧来源 |

## 当前边界

本轮建立了可靠的同步前置数据，但尚未开放“同步 PSD”。现有图集打包器的合并语义是保留全部旧区域；直接重复导入会累积旧 PSD 页面。正确同步还需要按映射替换旧区域，并在图层增删时迁移槽索引、附件时间线及用户后续编辑，不能用再次导入冒充同步。

第五轮列出的通用 Setup/动画补偿、复杂网格轮廓、更多坐标变换和视口工具等差距仍然存在。
